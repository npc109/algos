# 347. Top K Frequent Elements

**Сложность:** Medium  
**Источник:** [LeetCode](https://leetcode.com/problems/top-k-frequent-elements/)  
**Темы:** Hash Map, Heap, Bucket Sort

## Описание

Дан массив `nums` и число `k`. Вернуть `k` наиболее часто встречающихся элементов в любом порядке.

**Важно:**
- Ответ — `k` **различных значений**, а не счётчиков
- При равных частотах годится **любой** набор: ответ не определён однозначно, поэтому тесты проверяют свойство («частота каждого значения вне ответа не выше частоты любого из ответа»), а не конкретный массив
- `PriorityQueue<int[]>` с компаратором по частоте держит `k` самых частых: `poll()` снимает минимальную частоту
- Куча не лучше сортировки в худшем случае: при `k`, близком к числу уникальных, `O(u log k)` → `O(u log u)`
- Линейный вариант существует: частота не больше `n`, поэтому значения можно разложить по бакетам с индексом-частотой (`counting sort`), без сравнения частот

## Сложность

- **Время:** `O(n + u log k + k log k)`, где `u` — число уникальных. Худший случай `k = u`: `O(n + u log u)`
- **Память:** `O(u + k)` — карта частот и куча
- **Линейный вариант (бакеты):** `O(n)` по времени, `O(n)` по памяти

## Примеры

| Вход | Выход |
|------|-------|
| `nums = [1,1,1,2,2,3], k = 2` | `[1,2]` |
| `nums = [1], k = 1` | `[1]` |
| `nums = [1,2], k = 2` | `[1,2]` |
| `nums = [1,2,3,4,5], k = 3` | любой набор из трёх — все частоты равны |
| `nums = [-1,-1,-2,-2,-2,-3], k = 2` | `[-2,-1]` |

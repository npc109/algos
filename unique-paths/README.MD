# 62. Unique Paths

**Сложность:** Medium  
**Источник:** [LeetCode](https://leetcode.com/problems/unique-paths/)  
**Темы:** Dynamic Programming, Math, Memoization

## Описание

Робот стоит в левом верхнем углу сетки `m × n`. Двигается только вправо или вниз. Вернуть число различных путей до правого нижнего угла.

**Важно:**
- `dp[i][j] = dp[i-1][j] + dp[i][j-1]`: пути сверху и слева не пересекаются — последний шаг у них разный
- Первая строка и первый столбец равны `1` **как следствие** рекуррентности (в них ведёт единственный путь), а не отдельное правило
- Ответ равен `C(m + n - 2, m - 1)`: путь — это строка из `m-1` шагов вниз и `n-1` вправо
- **`int` не хватает для `m = n = 100`**: `C(198,99) ≈ 2,27·10^58`, не влезает и в `long`. Первая сетка до `100×100`, где `int` переполняется, — `m = 8, n = 70`; таких сеток 8040 из 9801
- Поэтому решение держится на гарантии условия «ответ в `[1, 2·10^9]`», а не на типе
- Кэш `c[m][n] != 0` корректён только потому, что для всех клеток сетки ответ `>= 1`

## Сложность

- **Время:** `O(m · n)` с мемоизацией; без неё — `C(m+n-2, m-1)` вызовов, то есть ответ задачи
- **Память:** `O(m · n)` на кэш и глубину рекурсии. Можно `O(n)`: держать одну строку `dp[j] += dp[j-1]`, так как каждой клетке нужна только верхняя и левая

## Примеры

| Вход | Выход |
|------|-------|
| `m = 3, n = 7` | `28` |
| `m = 3, n = 2` | `3` |
| `m = 1, n = 100` | `1` |
| `m = 100, n = 1` | `1` |
| `m = 5, n = 5` | `70` |
| `m = 10, n = 41` | `2054455634` — максимум, влезающий в `int` |

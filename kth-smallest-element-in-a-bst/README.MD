# 230. Kth Smallest Element in a BST

**Сложность:** Medium  
**Источник:** [LeetCode](https://leetcode.com/problems/kth-smallest-element-in-a-bst/)  
**Темы:** Tree, DFS, Binary Search Tree, In-order

## Описание

Дан корень BST и число `k`. Вернуть `k`-й **наименьший** элемент (нумерация с 1).

**Ограничения:** `1 <= k <= n <= 10^4`, `0 <= Node.val <= 10^4`.

## Алгоритм (in-order с ранним выходом)

In-order обход BST (левый → узел → правый) выдаёт значения **по возрастанию**. Значит, достаточно считать посещённые узлы и остановиться на `k`-м.

Наивно можно собрать всё в список и взять `k-1`-й элемент — `O(n)` времени, `O(n)` памяти. Оптимально — обходить in-order и **выйти раньше**, не доходя до правой части дерева.

Ответ пробрасывается наверх через возврат: как только найден, рекурсия не продолжается.

**Сложность выигрыша:** `O(h + k)` вместо `O(n)`. `h` — спуск до самого левого узла (чтобы найти минимум, надо дойти до конца влево), `k` — обход `k` узлов. На сбалансированном дереве с маленьким `k` это `O(log n)` вместо `O(n)`. На вырожденном `h = n`, и выигрыша нет.

## Реализация

Счётчик `cur` кодирует **и состояние, и результат**:

- `cur <= 0` — «продолжаем», значение `cur` = `-(посещено) - 1`
- `cur > 0` — «ответ найден», пробрасывается наверх через стек

Сдвиг счётчика происходит в двух местах: выход из `null` даёт `-1` (пред-инкремент для крайнего левого узла), уход вправо даёт `cur - 1` (текущий узел посещён). Спуск влево счётчик не меняет — изменения приходят снизу через возврат.

## Сложность

- **Время:** `O(h + k)`; `O(n)` в худшем случае
- **Память:** `O(h)` — стек рекурсии

## Ошибки при решении

| Ошибка | Причина |
|---|---|
| Условие ослаблено до `k + cur <= 0` вместо `==` | отладка вслепую: непонятно было, что означает `cur` |
| Не смог объяснить, почему `cur` не меняется при спуске влево | асимметрия счётчика: влево — придёт снизу, вправо — сдвиг руками |

**Корень обеих:** `cur` означает `-(посещено) - 1`, а не «посещено». Инвертированный счётчик заставляет каждый раз переворачивать знак в голове. Прямая формулировка — растущий `cur` и условие `cur == k`.

## Зависимость от ограничения

Решение опирается на `Node.val >= 0`: `cur > 0` различает «ответ» и «продолжаем».

**Открытый вопрос:** если `Node.val` может быть отрицательным, `cur > 0` перестанет различать состояния. Решение — вернуть `Integer`, где `null` = «не найдено» (тот же приём, что в Validate BST).

## Примеры

| Вход | k | Выход |
|---|---|---|
| `[3,1,4,null,2]` | 1 | `1` |
| `[5,3,6,2,4,null,null,1]` | 3 | `3` |
| `[3,1,4,null,2]` | 4 | `4` |
| `[10,5,15,3,7,12,20,1]` | 1 | `1` |

# 1584. Min Cost to Connect All Points

**Сложность:** Medium  
**Источник:** [LeetCode](https://leetcode.com/problems/min-cost-to-connect-all-points/)  
**Темы:** Graph, MST, Union-Find, Prim, Kruskal

## Описание

Даны точки `points[i] = [xi, yi]`. Стоимость соединения двух точек — **манхэттенское расстояние** `|xi-xj| + |yi-yj|`. Вернуть минимальную суммарную стоимость, чтобы все точки были связаны.

Это задача о **минимальном остовном дереве (MST)**.

## Теория: что такое MST

Подмножество рёбер, которое:
1. **связывает все вершины** — между любыми двумя есть путь;
2. имеет **минимальную суммарную стоимость**.

В дереве с `n` вершинами ровно **`n - 1` ребро**. Если рёбер больше — появится цикл, и одно ребро можно выкинуть, уменьшив стоимость. Значит минимум всегда содержит ровно `n-1` рёбер.

**Граф здесь неявный.** Рёбер не дано — их надо построить: каждая пара точек даёт ребро. Итого `n(n-1)/2` рёбер (полный граф).

## Реализация 1: Краскал (`kruskal/KruskalSolution.java`)

```
1. Построить ВСЕ рёбра: {расстояние, i, j}
2. Отсортировать по расстоянию
3. Идти по рёбрам: если концы в разных компонентах — добавить, объединить
4. Остановиться на n-1 рёбре
```

Проверка «создаст ли цикл» — через **Union-Find**: если `find(i) == find(j)`, точки уже в одной компоненте, ребро создаст цикл.

- **Память:** `O(n²)` — все рёбра материализованы
- **Время:** `O(n² log n)` — доминирует сортировка

## Реализация 2: Прим (`prim/PrimSolution.java`)

```
1. Точка 0 — в дереве
2. Положить в очередь рёбра от неё до всех остальных
3. Вынуть минимальное: если точка уже в дереве — пропустить,
   иначе добавить её и положить рёбра от неё к непосещённым
4. Пока не добавили все n точек
```

**Отличие от Дейкстры:** в очередь кладётся `(расстояние между точками, индекс)`, а **не** накопленное расстояние. В Дейкстре `dist[v] = dist[u] + w` — суммируется. В Приме — **вес одного ребра** до дерева.

- **Память:** `O(n)` — рёбра считаются на лету
- **Время:** `O(n² log n)` с кучей

## Сравнение

| | Краскал | Прим |
|---|---|---|
| Рёбра | все `n²/2` заранее | на лету |
| Память | `O(n²)` | **`O(n)`** |
| Структура | сортировка + Union-Find | `PriorityQueue` + `visited[]` |
| Строк кода | ~45 | **~30** |

**Прим элегантнее** на неявном полном графе: не материализует рёбра.

## Union-Find: две оптимизации

```java
// сжатие путей — в find
while (parent[i] != i) {
    var cur = i;
    i = parent[i];
    parent[cur] = parent[i];
}

// union by size — меньшего к большему
if (size[fa] < size[fb]) {
    parent[fa] = fb;
    size[fb] += size[fa];      // размер растёт у НОВОГО корня
} else {
    parent[fb] = fa;
    size[fa] += size[fb];
}
```

Вместе дают амортизированную `O(α(n))` — почти константу.

**Ловушка:** размер обновляется у того, кто **становится корнем**. Если обновить у `fa` и сделать корнем `fb`, `size` начнёт врать (проверено на данных).

## Ошибки при решении

| Ошибка | Причина |
|---|---|
| `if (size[fa] > fb)` — сравнение размера с индексом | `fb` — корень, а не размер |
| `parent[fa] = fb` при `size[fa] > fb` | перевёрнуто: большее присоединялось к меньшему |
| `if (c == points.length) break` | нужно `n-1` рёбер, а не `n`; условие было мёртвым кодом |
